# 路线选择与数据集方案

## 推荐结论

课程项目优先做路线一，路线二作能力与成本对照；能获得独立录音轨道时再做路线三。研究问题设为：“输入重叠比例与录音方式如何影响会议摘要的事实完整性？”这样比仅调用一次摘要 API 更能体现语音信息处理部分。

中文演示建议由小组录制短会议，明确征得参与者同意，准备人工转写与摘要。公开可复现实验优先使用 AMI 的选定会议；其英语内容应与中文实验分开统计。不能在没有统计的情况下把某整个数据集称为“低重叠”。

## 数据集比较

| 数据 | 可用内容 | 本项目中的用途 | 注意事项 |
|---|---|---|---|
| AMI | 英语会议录音、混音/头戴麦、手工转写及部分会议摘要 | 三路线共用会议、录音条件对照 | 有重叠；并非每场每种标注都齐全；先检查文件 |
| AliMeeting（SLR119） | 中文近场/远场会议语音与标注 | 中文重叠场景压力测试 | 不是现成的完整摘要金标准；需自行标摘要 |
| AliMeeting4MUG | 中文会议理解/生成标注 | 中文文本摘要模块验证候选 | 与 SLR119 不能仅凭相似名称配对；核查音频获取与会议ID |
| QMSum | 查询驱动的会议转写与参考答案 | 文本模型对照或后续查询式摘要扩展 | JSON 中的文本不是录音；问题与答案必须匹配 |
| 自录会议 | 自行控制录音轨道、重叠与任务 | 中文原型、可控对照 | 样本小、代表性有限，应独立报告 |

AMI 官方下载页列出了混音与独立头戴麦录音选项，也给出标注 ZIP；当前页面说明公开信号、转写和部分标注采用 CC BY 4.0。项目下载脚本默认 ES2002a，并保留来源记录。[AMI 官方下载页](https://groups.inf.ed.ac.uk/ami/download/)

AliMeeting 官方页面提供中文多通道会议数据，含8通道阵列与参与者头戴麦，采用 CC BY-SA 4.0；适合检验真实多说话人挑战，不应为了“好看分数”只用简单片段后声称解决了整个数据集。[AliMeeting 官方页面](https://openslr.elda.org/119/)

MUG 论文介绍了面向中文会议理解与生成的任务和数据；选用前还需核实实际可获得的数据版本及音频授权。[MUG 论文](https://arxiv.org/abs/2303.13939)。QMSum 官方仓库提供查询式摘要数据，使用时保留原查询和划分；本项目当前实现的是通用会议摘要，不宣称直接复现 QMSum 指标。[QMSum 官方仓库](https://github.com/Yale-LILY/QMSum)

## 最小可行数据计划（建议，尚非已完成实验）

1. 下载 AMI 一场会议，检查混音、参考转写、摘要。用于调试，不计入最终测试。
2. 中文自录至少6场，每场约3–8分钟；主题可为分工、选题、采购讨论。避免把预设剧本朗读当作自然会议。
3. 公开数据再选至少6场完整会议：2场开发、4场测试。小规模结果只作课程验证，不能宣称大规模泛化。
4. 每场记录 meeting_id、来源、语言、时长、说话人数、轨道类型、参考文本/摘要路径、重叠率、split、许可。分割在会议级完成，同场切片不能跨开发/测试；AMI 的同一场景系列最好整体分组。
5. 依据参考标注计算重叠率，在开发集确定分层阈值，再固定测试集。低重叠和高重叠都保留，不能用 ASR 输出筛选“表现好的会议”。

音频与标注对齐以官方 meeting_id 和时间基准为准。`prepare_ami.py` 将词标注按间隔聚合为短句，便于查看；聚合后的时间区间会包含短停顿，因此由该文件计算的重叠率只是近似。严格重叠率应直接使用官方说话人活动/词级时间标注，记录采用的定义。

## 为什么重叠难处理

单通道录音在同一时刻叠加多个人声，普通 ASR 可能只输出较响的人声；VAD 只判断是否有人声，说话人日志只标记谁在何时说话，两者都不会自动把混合波形拆开。降噪也不能一般性地替代人声分离。

更合适的工程方案是从采集端获得参与者独立轨道，或在单通道条件下采用“重叠检测→分离/目标说话人提取→逐路识别→对齐归并”。后一方案需要额外模型、域适配和评测，不在当前已实现范围内；时间有限时不建议为了凑三条路线盲目添加分离网络。

本实现选择前一种：先减少混合难度，再识别与摘要。但头戴麦也可能录到其他人；因此路线三应报告串音、重复条目和负责人错误，不能只报告整体字错率。

## 其他可扩展方案

- 云端会议转写 API（带时间戳/说话人）→文本大模型：通常比通用音频大模型更便于审计，但依赖厂商、地域和价格。当前不包含独立适配器。
- 人工转写→LLM：用于定位摘要模块错误，是上限对照，不是替代语音部分。
- 本地文本模型服务→同一兼容客户端：可减少内容外传；必须保证模型能按 JSON 输出，硬件由模型规模决定。
- 针对“谁负责什么”的检索式问答：可在现有片段证据索引上扩展，但不能把未实现的检索增强生成写进本项目实验成果。
